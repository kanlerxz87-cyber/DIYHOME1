Privacy & self-hosted analytics

Privacy-preserving click & conversion measurement

Turned on before any guide is written. Outbound clicks and the five defined events are measured locally, with best-effort delivery to a self-hosted collector endpoint. No cookies, no personal identifiers, no third-party trackers.

What is measured

  • page_view — a page is loaded
  • guide_view — a question-shaped guide is opened
  • table_view — the product dashboard table is opened
  • outbound_click — a visitor clicks an outbound product (sponsored) link
  • conversion_attempt — an outbound click carrying product conversion intent

The five defined events are not enumerated in the project brief, so this minimal set is defined here and flagged for confirmation (see /flagged.html and COORDINATION.md T-007).

How it works

  • Events are first-party only: event type, product code (short-link code only, never a resolved ASIN), page path, and a timestamp.
  • Nothing identifies an individual. No cookies are set or read.
  • Events are sent as best-effort beacons to the self-hosted collector endpoint /api/collect. If the endpoint is unreachable (static hosting has no backend), events are held in the browser's session storage and retried; they are never sent to a third party.
  • The collector endpoint route is defined in the site. Persisting events requires a backend; on GitHub Pages (static) the client queues locally. A backend handler is a follow-up task, not a blocker of the live site.

Reader capture

Email signup (where offered) is acknowledged locally only. No address is stored or transmitted by this static site.
