Executive summary · 21 November 2026

What this build contains, and what it proved

One page for the reader who will not read the site: what was verified, what was refused, what is still blocked, and where every claim traces to.

Second pass, 21 November 2026

Several sessions re-read this site’s sources on the same day without coordinating. Their findings agree, and the record is the union of them. This section covers only what the later pass added.

  • The Product Information tables were reachable after all. F16 recorded that Amazon did not render them on 21 November. That was true of the desktop page; /gp/product/<ASIN> does render them. 11 fields of B08FKW9JRM and 10 of B0BSKQW2T2 were re-confirmed verbatim against those tables.
  • What still could not be confirmed was downgraded, not kept. B08DY9HRWD kept serving the reduced layout, so its model number, manufacturer part number, UPC, per-tier limit and included components, plus the “Ships from / Sold by” line for all three listings, are kept exactly as recorded on 20 November and badged Needs Review. The register reads 29 Verified / 13 Needs Review / 10 Unverified across 52 rows. No value was re-typed or inferred.
  • Three build defects fixed. “How we verify” described the listing title and breadcrumb as the only published product attributes, contradicting the 52-row register; the comparison matrix printed Needs-Review values as plain facts; the audit engine labelled all 52 rows “verified” regardless of status. All three now report what is actually true.
  • Not re-run by the table-re-read pass: the link.amazon submission fetches (a parallel session did fetch all three on 21 November; see the next section). A further unattended automated request against an Amazon page is the conduct Agent Terms 4 makes disclosable (S01, F13). The register shows the truth per link: short links 1 and 3 carry a 21 November retrieval, short link 2 is dated 20 November, so all three observations are dated rather than presented as fresh.

What was verified

  • Three supplied short links each resolved to a live Amazon product page, and the final URL and listing title were recorded: B08FKW9JRM (Art3d smoothing tool kit), B0BSKQW2T2 (paper towel holder), B08DY9HRWD (ORDORA 8-tier pan organiser).
  • The short-link tokens are not ASINs: they contain lowercase letters, and /dp/B0HMGG4M2 returned no product page. ASINs are recorded from the resolved pages, in a separate field from the intended value.
  • Amazon’s Associates Program Policies and Operating Agreement were read directly, including the clauses that govern price display, review and rating display, link cloaking, link shortening, price tracking and automated agents.
  • FTC disclosure guidance was read directly, and the disclosure strip placement follows it: under the masthead, above the content, on every page, repeated in the footer.
  • GitHub Pages is enabled on this repository with the legacy build from main:/, so the site publishes from the repository root with no build step on GitHub’s side.

What was refused

  • No prices, star ratings, review counts, availability or product images, because this site has no Amazon-served link widget and no Creators/PA API access.
  • No commission percentages, conversion scores or revenue forecasts, because the rate schedule and the reports both require a sign-in.
  • No hands-on experience claims, because nothing was bought or used.
  • No inferred catalog values: where UPC or Date First Available is absent from an official listing table, the cell stays blank and badged unverified.
  • No search-volume or popularity claims for any guide title.

What the 21 November 2026 pass changed

  • Short-link tracking, re-examined. All three supplied links were fetched again and resolved to the same ASINs. None carries the tag in its redirect, and Amazon's own help topic says the tracking ID is not expected to appear there because the session is tagged instead. S30 That is why the flag is about the Associates report, not about the missing parameter.
  • The ASIN definition is now first-party and public. Amazon defines the ASIN as its 10-digit item code and documents the link format used here. S31
  • Commission bands are public. Kitchen 4.50%, Home/Home Improvement/Tools 3.00%. S32 The band is not the payout, so no percentage is published and the ledger stays empty.
  • Blanks now explain themselves. Every unverified field says what was checked and when — two listings expose no UPC, two expose no date first available.

What is still blocked

  1. F01 The three submitted short links are not confirmed as enrolled Associates Special Links — Sign-in to Associates Central, open SiteStripe, build one link per product, confirm the destination and confirm the click in the tracking report before adding more products.
  2. F03 The air-fryer working titles in the brief have no matching products — Either submit air-fryer products, or accept the replacement guide set.
  3. F04 Search Console is not verified: no verification token was available — Add the property in Search Console, copy the HTML tag, paste it into data/site.json as search_console_token, rerun the build.
  4. F05 The analytics endpoint is not deployed, so the five events stay in the browser — Deploy worker/collect.js, then set the endpoint in data/site.json and rebuild, or paste it into assets/js/config.js at runtime.
  5. F10 Commission rates could not be verified, so no commission percentages or revenue forecasts appear — Read the rate card inside Associates Central and record it with a date, then it can be shown as a dated fact.
  6. F13 The verification fetches did not identify themselves as an automated agent — Any automated refresh must set a user agent of the form Agent/diyhome-verifier and must not work around blocks. If Amazon asks an agent to stop, it stops.
  7. F17 Two public source registers used the same S-numbers for different documents — Nothing blocking; data/sources.json is the canonical register and is the one rendered on /sources/.

How the site is built

Every page is generated from data/*.json by scripts/build.mjs. No page is hand-edited, so the disclosure strip, the navigation, the canonical URL and the link attributes cannot drift between pages. scripts/validate.mjs then enforces: one h1 per page, a disclosure on every page, rel="sponsored nofollow" on every Amazon link, the correct tag on every product URL, no cloaked redirects, every internal link resolving, every page in the sitemap, and a well-formed feed.

Where the numbers will come from

Five events are instrumented and firing in the browser: page_view, disclosure_view, outbound_click, site_search, guide_read. They are queued locally and sent nowhere until an endpoint is deployed. The campaign ledger stays empty until a dated first-party report exists. That is the whole measurement story, and it is deliberately boring.
